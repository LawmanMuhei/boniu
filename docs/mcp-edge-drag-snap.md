# 拖动时的边缘吸附与越界阻挡

## 需求来源

用户反馈原文：

> 当用户把程序拖到屏幕的边缘的时候……比如想拖到屏幕右侧边缘，整个程序会有一半进入到屏幕看不见的地方。
> 当程序靠近屏幕边缘时，即程序的最右边快要进入屏幕的最右边时，直接吸附过去，不能再往右边飘动。

已确认的三项决定：

| 决定 | 结论 |
| --- | --- |
| 覆盖哪几条边 | **只吸左右两边**（上下不做限制，窗口仍可被拖出上下边界） |
| 显示器 | 用户为**单屏**环境（多显示器接缝问题按"不做处理但留正确写法"处理） |
| 是否加开关 | **不加**，直接一直生效 |

## 交互

1. 按住标题栏拖动窗口，靠近屏幕左/右边缘 16 设计像素以内 → 窗口**贴齐该边缘**。
2. 继续往屏幕外拖 → 窗口**不动**（不会再有半个窗口露在屏幕外）。
3. 反向往屏幕内拖 → **立刻跟手**，没有"先黏住一段才肯走"的死区。

## 顺带修掉的缺陷（比新功能更重要）

`WindowRules.ResolveEdgeDockSide` 原来用**绝对值**判距离：

```csharp
int rightDistance = Math.Abs(bounds.Right - workArea.Right);
bool right = rightDistance <= threshold;   // 16 设计像素
```

于是窗口只要越过屏幕边缘超过 16 像素，判定就是 `None` 而不是 `Right`——**贴边自动隐藏既不收起也唤不回**，窗口滞留在屏幕外。而这种情况在真机上极易发生：

> 拖动时窗口右边缘 = 光标位置 + (窗口宽度 − 抓标题栏的位置)。
> 窗口宽 420、抓标题栏中间，窗口右边缘就比光标**再多出 210 像素**；把光标拖到屏幕最右边松手，窗口超出屏幕 210 像素，判定直接落空。

改成"贴到或**越过**都算"（`bounds.Right >= workArea.Right - threshold`），并保留"两侧都够近时取更近一侧"的取向。这样冲过头的窗口会在松手时被拉回贴齐并正常收起。副作用是好的：把窗口拖到完全看不见的地方，松手也会被救回屏幕边缘。

## 实现要点

- **用 `WM_MOVING`，不自己接管拖动。** 拖动走的是 Windows 原生移动循环（`MainForm.DragWindow` 里 `ReleaseCapture()` + `SendMessage(WM_NCLBUTTONDOWN, HTCAPTION)`），系统会在循环中持续发送 `WM_MOVING`，`lParam` 指向"系统打算把窗口放到哪"的 RECT，**允许程序修改**——这正是留给移动时约束/吸附的口子。改它不用和模态循环抢控制权，也不会抖。
- **`SnapSideEdges` 是纯函数**，输入提案矩形、当前矩形、工作区与接近阈值，便于自测覆盖各种边界。
- **反向拖动立刻放手。** 判据是 `proposed.Left <= current.Left`（左）/ `proposed.Right >= current.Right`（右），即"没有在往屏幕内退"。不设"离开阈值"，否则窗口贴在边上时要先用力拖十几像素才动。
- **只改横向。** 纵向位置一律原样返回，吸边不该顺手改用户的高度和上下位置。
- **横向用提案矩形算工作区。** 取 `Screen.FromRectangle(proposed).WorkingArea` 而不是当前 `Bounds` 所在的屏幕：多显示器下后者会把窗口永远挡在原来那台显示器上（那台显示器的边缘在桌面中间，不是真正的桌面边缘）。单屏下两者等价。
- **窗口比工作区还宽时直接返回**，不去硬挤某一侧。
- 日志：一次拖动只记一条 `edge-snap proposed=… snapped=…`（由 `WM_ENTERSIZEMOVE` 复位标志），否则拖动过程中每个 `WM_MOVING` 都会刷屏。

## 已知限制

- **上下两侧不限制**：窗口仍可以被拖出屏幕上下边界（用户明确选择只吸左右）。
- **缩放（`WM_SIZING`）不受约束**：从边框拖动缩放仍可把窗口的边拉出屏幕。本次只处理"移动"手势，没有顺手加进去。
- 多显示器时只在"整个桌面外框"那几条边上吸附是对的，但当前实现按提案矩形所在屏幕取工作区；跨屏接缝附近的极端位置未做专门处理（用户为单屏环境）。

## 验证

- 自测新增 11 项：贴边判定"冲过左右边缘仍算贴边"2 项；`SnapSideEdges` 的"远处不干预 / 靠近左右贴齐 / 冲出左右拉回 / 反向拖动不黏住 / 只动横向 / 两侧同时命中取近侧 / 与工作区同宽时不吸附"9 项。
- 回归新增 6 项：把提案矩形塞进 `WM_MOVING` 的 `lParam` 真实发给窗口，验证冲过右边缘被拉回贴齐、冲过左边缘被拉回贴齐、离两侧都远时原样返回；再用真实窗口把位置直接设到屏幕右侧外 300 像素并调用 `EvaluateEdgeDock()`，验证**仍能收起并隐藏**，且显式恢复能解除贴边。
- **真实拖动时系统是否真的发送 `WM_MOVING` 无法在自动化测试里合成**（需要真人按住鼠标拖）。上面的探针走的是同一条消息通路，但"系统会发这条消息"属于文档行为，仍需真机确认：拖到边缘应该贴齐且拖不出去；`run.log` 里应出现 `edge-snap proposed=… snapped=…`。
