# v1.11 阶段 3：独立记忆的网页缩放

日期：2026-10-27。

采用方案 A：启用 WebView2 原生 Ctrl+滚轮与触控板缩放；监听 ZoomFactorChanged，将有效比例除以电脑自适应系数，得到用户比例并规范化至 50%~200%。程序更新比例时使用 applyingZoom 标记。Resize 重新计算“用户比例 × 适配比例”，不会回写成旧的固定窗口比例。

Ctrl+0 因禁用浏览器快捷键而由文档创建脚本捕获，通过对象消息通知宿主，仅接受抖音 HTTPS 来源。普通滚轮不拦截。设置浏览卡片新增减号、百分比、加号、重置，每次按钮调整 10%。MobileZoomPercent / DesktopZoomPercent 分别保存。临时提示用独立 1200ms Timer，不改原有 7 秒消息计时器。

网页缩放包括网页文字、按钮和画面，窗口与工具栏尺寸不变。用户缩放为 100% 时，DesktopAutoFit 开启仍会乘适配系数；设置页显示用户比例，设备日志显示实际 ZoomFactor，二者含义不同。

check-version 1.11.0，C# 5 编译通过；x64/x86 各 134 项自测、87 项回归，5 个入口均 exit 0。新增回归模拟浏览器缩放事件后调用与 Resize 相同的 UpdateZoom，检查比例不被覆盖、双模式独立、Ctrl+0 消息、上下限与隔离目录中的保存/加载。

测试模式按原设计禁止自动保存计时器，首次验证中的“保存计时器启用”断言不适用，已替换为隔离 SettingsStore 的真实保存/加载断言。没有开启测试对真实配置的写入。

原生 Ctrl+滚轮/触控板的真实设备手感、抖音复杂 iframe 内的快捷键和移动模式下的实际交互仍需人工验收；合成事件断言不等于操作系统输入已验收。当前没有发现必须切换到方案 B 的证据，因此未同时保留另一套滚轮实现。
