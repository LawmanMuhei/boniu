# 小窗清晰度：超采样实测无效，改为解除抖音最小宽度

日期：2026-10-27。环境：用户机 2560×1440 / 32 寸（约 92 PPI），Windows 缩放 100%、**文本大小 114%**（WebView2 因此按 1.14 倍渲染，420 宽窗口的 CSS 视口约 369）。

## 探针

`--render-probe [--probe-output 目录]`（src/RenderProbeForm.cs）：独立匿名会话、静音、420×760 置顶小窗，打开真实推荐页，
对每种方案播放 5 秒统计帧率与丢帧，再用 `CopyFromScreen` 截**屏幕上实际显示的像素**，并记录 DPR、视口、互动按钮位置、WebView2 私有内存。

## 结论

| 方案 | DPR | CSS 视口 / 页面宽 | 互动栏 | 结果 |
| --- | --- | --- | --- | --- |
| 原生 100% | 1.14 | 369 / 580 | 456~502，**被裁** | 字清楚，但右侧裁掉 |
| CDP 2 倍超采样（deviceScaleFactor=2） | 2.0 | 369 / 580 | 被裁 | **与原生逐像素几乎一致**（左栏平均差 0.27/255，文字区边缘能量完全相同），无效 |
| 缩小适配 0.63 | 0.72 | 586 / 586 | 完整 | 布局完整，但字很小 |
| **100% + 解除 body min-width** | 1.14 | 369 / 369 | 245~291，完整 | 字大且清楚，播放器与互动栏完整 |
| 同上 + 清爽模式 | 1.14 | 369 / 369 | 完整 | 播放器铺满，效果最好 |

- WebView2 的合成器始终按真实显示比例光栅化，CDP 的 `deviceScaleFactor` 只改变网页读到的 `devicePixelRatio`；抖音也没有因此加载更高分辨率的图片（640 宽封面在 2 倍下仍是 640）。所以"按 2K 渲染再缩小"在这里做不到，也没有收益，未加入正式功能。
- 各方案均 60fps、0 丢帧，内存无显著差异。
- 抖音电脑版 `body{min-width:580px}` 是小窗被裁、以前不得不整页缩小的根源。现在由 `PageScripts.NarrowLayoutScript` 注入 `html,html body{min-width:0!important}`，单独一个 style，健康守卫回退时也保留。
