# v1.11 阶段 2：清晰度与 DPI

日期：2026-10-27。

## 改动与原因

手机模式不再按窗口宽度缩小整页，默认 ZoomFactor=1。电脑模式增加“自动适配宽度”开关，默认开启，自适应下限从 44% 提至 67%；关闭后按用户比例显示。有效比例为用户比例乘以适配系数，并限制在 0.25~5。两种模式各自的比例字段默认 100，保存时规范化为 50~200，为阶段 3 的用户缩放提供统一计算。

WM_DPICHANGED 按系统建议矩形更新窗口，复用 SetBoundsProgrammatically，更新 UI 比例、布局、圆角和重绘。UI 比例改用 GetDpiForWindow，入口不可用时才回到 Graphics.DpiX。不修改 WM_MOVING 和拖动吸附。

设备日志已记录 DPR 与 videoWidth/videoHeight。阶段 0 的相同窗口、相同显示环境对照：ZoomFactor 0.58 → 1.0，页面 DPR 0.6612 → 1.14，CSS 视口宽 636 → 369。截图为 `artifacts/verification/mobile-spike-inputs/desktop-058.png` 与 `desktop-100.png`。这证明页面缩放影响 DPR 与布局；该精选页尚未取得视频元数据，无法证明同一视频码流分辨率提高。手机页自身仍声明 initial-scale=0.5，所以不会承诺改变浏览身份后文字必然变大或素材必然高清。

可选 P3“优先最高画质”跳过：虽在页面文字中观察到“智能”，没有经过实际点击确认的稳定菜单结构，不猜测选择器、不反复点击播放器。

## 验证与边界

check-version：1.11.0；C# 5 编译通过；x64/x86 每种架构 134 项自测、81 项合成回归，5 个入口均 exit 0。新增断言覆盖手机原始比例、电脑关闭适配、67% 下限及用户比例相乘。

多显示器实际 DPI 迁移、系统缩放变化的手工观感、同一登录账号同一视频的码流前后对照未验收。WM_DPICHANGED 的实现与合成布局测试不能替代这些结果。
