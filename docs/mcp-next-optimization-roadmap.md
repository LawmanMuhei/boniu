# 下一轮优化路线建议

日期：2026-09-22。范围：基于当前未提交源码、既有实施记录、剩余优化清单和 UI 复审重新排序；本文件只给出路线，不修改业务代码、不构建、不发布。

## 总体判断

当前项目的核心能力已经齐全，昨天还完成了主窗拆分、隐藏/恢复竞态治理、WebView 挂起修复、更新测试、老板键弹窗清场和 P1 UI 修复。下一步不宜继续堆大功能，优先把这批未提交改动固化并完成真实抖音页面人工验收，然后做低风险、高收益的可靠性、安全和交互收尾。

## 第一批：建议现在做

1. **自动隐藏防误触**：鼠标离开窗口去点右侧互动区域时增加小范围缓冲，鼠标按下/拖动期间暂停自动隐藏。保持抖音原生播放器和互动布局，不增加黑色侧栏，也不改变视频尺寸。
2. **统一恢复能力判断**：失焦隐藏由只检查窗口快捷键改为统一使用 `CanRestoreWindow`，让托盘恢复可用时不再错误阻止隐藏。
3. **收紧异步异常路径**：把三个 `async void` 入口改成可追踪的 `Task` 调度，所有 fire-and-forget 异常写入 `Diagnostics`；为现有空 `catch` 增加最低限度日志。
4. **修正参数引用**：按 Windows `CommandLineToArgvW` 规则重写 `Bootstrap.QuoteArgument`，补 Unicode、空格、引号和尾反斜杠往返测试。
5. **磁盘轮换清理**：旧负载目录保留当前版和上一个版本；更新设置备份保留最近三份；成功更新后按安全条件清理过期 `.bak`。
6. **真实页面验收清单**：固化清爽模式、互动按钮、直播弹层、登录、音频、锁屏、多显示器 DPI、托盘与实际更新回滚步骤。先人工跑通，再提交和发布当前大批改动。

## 第二批：安全与性能

1. 更新下载增加 GitHub 主机白名单，避免 Release API 把下载重定向到任意 HTTPS 主机。
2. 构建脚本为固定版本 WebView2 NuGet 包校验预置 SHA-256。
3. 自动隐藏关闭时停止 10ms 光标轮询；随后评估 `TrackMouseEvent` 事件驱动，保留低频兜底而不是一次性重写。
4. 清爽模式健康检查由永久 1.5 秒布局测量改为 `MutationObserver` 或稳定一段时间后停表。
5. 直播状态从周期 `ExecuteScriptAsync` 逐步改为页面事件推送，减少 WebView IPC。
6. 发布脚本增加 `-WhatIf`，只打印资产、架构、哈希和目标 Release，不执行上传。

## 页面与可访问性

1. 完成 P2：工具栏支持 Tab、所有自绘控件绘制可见焦点环、关键控件补 `AccessibleName` / `AccessibleRole`。
2. 缩放把手按 DPI 放大；滚轮按系统三行习惯滚动；被省略的长文案提供完整 tooltip。
3. 设置页增加简洁的“诊断信息”卡片：版本、架构、WebView2 Runtime、数据目录、最近错误状态，并提供“复制诊断信息”；不得包含 Cookie、登录令牌或网页存储内容。
4. 托盘入口建议默认开启，或首次启用自动隐藏时明确提示托盘恢复位置，降低用户误以为程序消失的概率。

## 新功能优先级

### 值得做

- **一键导出脱敏诊断包**：日志、版本、架构、运行时版本和设置摘要，显著降低页面适配失效的排查成本。
- **临时暂停自动隐藏**：例如托盘菜单或设置页提供 5/15/30 分钟暂停，适合需要连续操作评论、登录或设置的场景。
- **关闭按钮行为可选**：退出程序或最小化到托盘，默认行为保持不变，避免突然改变用户习惯。
- **可选开机启动并驻留托盘**：必须明确可关闭，不做静默安装，不绕过 Windows 启动项管理。

### 暂缓

- 多账号配置档：需要隔离 UserData、缓存清理、更新和迁移，复杂度与隐私风险较高。
- 屏幕边缘“窥视”预览：容易与隐藏可靠性、DPI 和多显示器逻辑冲突。
- 滚轮调音量/倍速：容易抢占抖音原生滚动手势，除非用户需求明确。
- 老板键双击退出：误触代价高，不建议默认提供。

## 推荐执行顺序

先完成第一批 1-6，并跑 x64/x86 自动测试与真实页面验收；随后提交一个稳定基线。第二批按“更新安全 → 低风险性能 → 发布体验”推进。新增功能首选脱敏诊断包和临时暂停自动隐藏，暂不碰多账号与播放器几何控制。
