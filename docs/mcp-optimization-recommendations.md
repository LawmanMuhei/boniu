# 优化建议（静态阅读后的初步判断）

## 范围与原则

依据 docs/mcp-project-overview.md 所列阅读结果，以下是候选优化，不是经过运行验证的缺陷清单。本次不修改业务代码，也不执行构建、更新、发布或性能测试。优先保证隐藏可靠、恢复正常、页面适配可回退，再考虑增加功能。

## 第一优先级：隐藏与恢复可靠性

- src/MainForm.cs 的 HideWindow 在 Hide 前调用 WebView 静音和异步脚本。建议实测这些调用在页面卡顿时是否拖慢窗口隐藏，再调整为隐藏路径尽量不依赖网页响应，并兼顾立即静音，避免仅将静音延后产生漏音。
- 显示/隐藏、暂停/恢复、挂起/唤醒、设置页、直播横竖屏存在多个异步状态。建议用操作代次或明确状态转换约束过期结果，重点回归连续快速切换，确认不存在恢复后被旧暂停操作覆盖的情况；此为待验证风险。
- 锁屏隐藏目前受恢复快捷键可用性限制。建议把恢复入口与会话安全策略共同设计，可考虑可选托盘菜单和快捷键冲突时的可见提示，不宜只删除保护条件导致用户无法恢复窗口。

## 第二优先级：页面适配与用户反馈

- 保留原生播放器布局和已有样式健康回退，不继续扩大侵入式播放器样式覆盖。
- 把页面选择器、注入脚本与窗口逻辑分离；按普通视频、直播、登录和设置返回场景维护适配规则。
- 回退发生时显示不遮挡播放的简短提示，并提供手动重新应用清爽样式入口，避免用户误以为设置失效。
- 回归短视频连续切换、直播弹层、横竖屏切换、设置往返、不同 DPI 和网页加载失败。

## 第三优先级：可维护性与验证

- src/MainForm.cs 当前 2897 行，可逐步拆分隐藏/恢复控制、页面适配、快捷键和设置视图。一次提取一个职责，保持行为不变，避免整体重写。
- 复用 src/Program.cs 已有自测与冒烟测试入口，补充明确的回归用例、结果记录和 x64/x86 构建验证，不另建重复测试机制。
- 先建立 CPU、内存、隐藏延迟、恢复延迟的基线，覆盖播放、隐藏、挂起、恢复及连续切换场景。项目已有 WebView 挂起机制，不应把新增挂起当作尚未实现的优化。

## 低成本收尾

- 同步 README.md、波妞摸鱼-使用说明.txt、src/AssemblyInfo.cs、src/Bootstrap.cs、app.manifest 的版本与平台信息；长期可考虑集中版本来源并在构建时校验。
- 在现有更新校验与回滚基础上，验证断网、下载中断、目标目录不可写、健康检查超时等失败路径和用户反馈；当前未判定这些场景存在故障。
- 若扩大分发，再评估正式代码签名。SHA-256 配套文件提供完整性校验，但不等同于独立发布者身份认证。

## 建议实施顺序

先建立最小运行基线并复现隐藏/恢复边界场景，再修复已确认问题；随后整理页面适配模块与回归用例，最后评估性能优化和新增体验功能。具体优先级应结合实际用户遇到的问题调整。
